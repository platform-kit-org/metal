## Symptoms

<dl>
  <dt>[](kind:TalosCluster)</dt>
  <dd>`Available=False` with `KubernetesUnreachable` or `NodesNotReady`.</dd>
  <dt>[](cli:status)</dt>
  <dd>The `AVAILABLE` column of the cluster. Exit status 2.</dd>
  <dt>Alert</dt>
  <dd>`PkMetalClusterUnavailable`, for 15 minutes. It fires only for a bootstrapped cluster. A cluster that the operator still builds does not page.</dd>
</dl>

## Impact

With `KubernetesUnreachable`, nobody can change the workloads of the cluster. With `NodesNotReady`, the workloads of some nodes do not run.

## Diagnose

Read the `AVAILABLE` and `ETCD` columns of the cluster in [](cli:status).

```sh
pk-metal status
```

## Fix

| Reason | `ETCD` | Go to |
| --- | --- | --- |
| `KubernetesUnreachable` | `EtcdUnavailable` | [](rb:etcd-unhealthy). etcd is the cause. |
| `KubernetesUnreachable` | `EtcdDataLost` | [](rb:bootstrap-refused) |
| `KubernetesUnreachable` | `EtcdRunning` | The API server or the endpoint is the cause. Check the control planes in [](rb:node-not-ready). |
| `NodesNotReady` | any | [](rb:node-not-ready). The message names the nodes. |

## Verify

`kubectl get taloscluster prod` shows `Available=True`. The alert resolves.
