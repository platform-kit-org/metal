The operator does not use PXE, TFTP or DHCP to install a machine.
It mounts the installer and the node configuration as virtual media on the BMC, and boots the machine from them one time.

<Provision start={3} />

## The sequence

1. [](act:EjectMedia) on each slot.
2. [](act:InsertMedia) for the installer. The operator downloaded it from the image factory and pins it by its digest.
3. [](act:InsertMedia) for the configuration. The operation pins the configuration by its digest.
4. [](act:SetBootOverride) to the virtual CD, one time, in UEFI mode.
5. [](act:PowerCycle).
6. [](act:AwaitCheckIn) until the node runs from its disk.
7. [](act:EjectMedia): the configuration first, because it holds the keys of the cluster.

## Why not PXE

- No DHCP or TFTP server is necessary on the machine network.
- A Talos machine without a configuration accepts one from each client that reaches it. The configuration holds the keys and tokens of the cluster. So it never goes over the network, only through the BMC.
- The BMC gets the media, so the machine needs no route to the operator.

## One-slot BMCs

A normal install needs two media: the installer and the configuration.
Some BMCs hold one medium only. For a blank machine behind such a BMC, the operator builds one installer for that node, with the configuration inside.

The imager runs as a Job in the namespace `pk-metal`. It reads the configuration from a file, not from its arguments. Talos 1.12 or later reads such an embedded installer.
The kustomize component `config/media-store` adds the media store. The [](kind:BootAsset) records the digest of each ISO, and the media service checks it each time a BMC downloads the file.

The operator builds the ISO for a boot. It deletes the ISO when no boot of the claim runs: after the install, or after a failed boot. A machine that already runs Talos needs no embedded ISO. Its configuration goes into the one slot as a small ISO. See [](ref:media-store#media-that-carry-secrets).

<Callout type="caution">
Treat the media store volume like the Secret storage of the cluster.
Each ISO holds a node configuration in plain text, readable only by the operator user.
</Callout>
