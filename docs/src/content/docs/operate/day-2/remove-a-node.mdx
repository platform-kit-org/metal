## Goal

Take one node out of its cluster. Give its machine back to the pool for another claim, or take the machine out of the fleet.

## Before you start

- You know the name and the namespace of the claim.
- The workloads can move to the other nodes.
- For a control plane: what remains of etcd is safe. See [Join and leave rules](howto:scale-a-cluster#join-and-leave-rules).
- A person with `pk-metal-approver` can approve. See [](howto:approval-permissions).

## What the release does

| The machine | The release |
| --- | --- |
| Was never installed by this claim | Powered off without a question. |
| Runs a node that answers | One operation: [](act:Drain), [](act:EtcdLeave) for a control plane, [](act:TalosReset), [](act:DeleteKubernetesNode), [](act:PowerOff). It waits for approval. The drain stops after 15 minutes. The reset wipes the system disk. |
| Ran a node that does not answer | etcd member removed by ID, Kubernetes node deleted, power off. The operator marks the Host as not wiped. |

<Callout type="warning">
Do not delete a claim to "stop managing" a machine, or when the machine has data that you must keep. The release wipes the disk.
A GitOps tool that prunes a deleted file deletes the claim too.
</Callout>

## Steps

<Steps>

1. Delete the claim of the node.

   ```sh
   kubectl -n default delete hostclaim w-3
   ```

   The Host goes to `Releasing`.

2. Approve the release.

   ```sh
   pk-metal approve pk-metal/release-simhw2288v5000399-8e7f6a5b
   ```

3. Monitor the Host.

   ```sh
   kubectl get host simhw2288v5000399 -w
   ```

   The phase goes from `Releasing` to `Available`.

4. To remove the node for good, delete its TalosNode. If you keep it, it waits without a machine for the next scale up.

   ```sh
   kubectl delete talosnode w-3
   ```

</Steps>

## Remove a control plane

The operator refuses a removal that leaves etcd unsafe. See [Join and leave rules](howto:scale-a-cluster#join-and-leave-rules).
The claim then shows `EtcdRiskRefused`. To accept the risk, annotate the claim with your reason. See [](ref:labels-annotations) for the value.

```sh
kubectl -n default annotate hostclaim cp-3 metal.platform-kit.org/ack-etcd-risk="alice: scale down to one control plane"
```

## Take the machine out of the fleet

<Steps>

1. Release the machine, as above.

2. If the Host shows `DiskWiped=False`, wipe it. See [](rb:disk-not-wiped).

3. Delete its [](kind:Asset).

   ```sh
   kubectl delete asset sim-0003
   ```

4. Remove its line from the ledger and apply the overlay.

5. Remove the BMC credentials Secret if no other Asset uses it.

</Steps>

<Callout type="note">
A claim holds the Host and its endpoint. The operator keeps them until the claim is gone (`DeletionHeld`).
</Callout>

## Verify

- The [](kind:Host) is `Available` and has no claim.
- `kubectl get talosnodes` does not list the node that you deleted.
- After you took the machine out of the fleet, `kubectl get hosts` does not list it.

## If it fails

| What you see | Go to |
| --- | --- |
| The drain step fails | [](rb:drain-stuck) |
| Claim blocked on `ReleaseFailed` | [](rb:operation-failed). Retry the release. |
| Host `DiskWiped=False`, `InstalledNodeRemains` | [](rb:disk-not-wiped) |
| TalosNode stays with `RemovalBlocked` | The message names what it waits for: the machine, or the etcd member. |
