`pk-metal completion` prints a completion script for your shell.
When your shell loads the script, the `tab` key completes the commands, the flags and the names of the objects in the cluster.

## Synopsis

<CliSynopsis cmd="completion" />

The command takes one argument: `bash`, `zsh` or `fish`. It has no flags.

## Install the completion

Do the step for your shell one time. Then open a new terminal.

<dl>
  <dt>bash</dt>
  <dd>The script needs the `bash-completion` package of your Linux distribution.</dd>
</dl>

```sh
echo 'source <(pk-metal completion bash)' >> ~/.bashrc
```

<dl>
  <dt>zsh</dt>
  <dd>Put the line after the line that runs `compinit`.</dd>
</dl>

```sh
echo 'source <(pk-metal completion zsh)' >> ~/.zshrc
```

<dl>
  <dt>fish</dt>
  <dd>The shell loads the file when you type `pk-metal` for the first time.</dd>
</dl>

```sh
pk-metal completion fish > ~/.config/fish/completions/pk-metal.fish
```

<Callout type="note">
The script runs the program that is on the command line. Thus `metal/bin/pk-metal <tab>` also completes when `pk-metal` is not on the `PATH`.
After an update of the program, open a new terminal. The bash and zsh scripts then load again.
</Callout>

## What it completes

| Position | Candidates |
| --- | --- |
| Command | The commands of the program, and `help` |
| Subcommand | For example `list`, `show` and `approve` after `rollout` |
| Flag | The flags of the command, with their help text in zsh and fish |
| Operation | [](cli:approve): the operations that wait for approval. [](cli:retry): the failed and the aborted operations. [](cli:abort): the operations that did not finish. |
| Claim, node | [](cli:hold), [](cli:unhold): claims. [](cli:reboot): TalosNodes. [](cli:reinstall), [](cli:replace): claims and TalosNodes. |
| Host | [](cli:wipe): all Hosts. `--host` of [](cli:replace): the Hosts that are `Available`. |
| Cluster | [](cli:scale), [](cli:upgrade), [](cli:backup), [](cli:restore): TalosClusters. `backup now` also completes EtcdBackupPolicies. |
| Snapshot, rollout | EtcdSnapshots and TalosRollouts |
| BMC address | [](cli:check), [](cli:inventory), [](cli:boot): the addresses of the ManagementEndpoints |
| Flag value | `-n`: namespaces. `--context`: the contexts of the kubeconfig. Files and directories for the flags that take them. Fixed values, for example `-o table` or `json`. |

For a namespaced object, the program completes the names in the namespace of `-n`, or in the default namespace of the command.
Type `<namespace>/` to complete the objects of that namespace in the form `<namespace>/<name>`.

## What it does

1. The shell calls the program with the words of the command line, each time that you press `tab`.
2. The program reads the flags of the command from the command itself. A new flag thus completes without a change to the script.
3. For an object name, the program reads the objects from the cluster that `--kubeconfig` and `--context` on the same command line select. Without these flags, it uses the same default as the other commands. See [](cli:global-flags).
4. Each lookup in the cluster stops after 2 seconds. If the cluster does not answer, you get no candidates and no error.

## Examples

<Terminal

## Objects

The command reads and writes no object. The completion reads Namespaces and the objects of the operator. It changes nothing.
