The virtual lab runs on a Linux workstation or a CI runner.
[](lab:doctor) checks each item on this page and prints the fix for each item that is missing.

## At a glance

<dl class="pk-glance">
  <dt>System</dt>
  <dd>Linux on x86-64 or ARM64, with cgroup v2. With KVM, the machines are fast. See [Operating systems](#operating-systems).</dd>
  <dt>Memory</dt>
  <dd>About 12 GiB free for the default size. `3cp+2w` needs about 19 GiB.</dd>
  <dt>Disk</dt>
  <dd>15 GiB free below `.lab/`</dd>
  <dt>Container engine</dt>
  <dd>Docker Engine, as root.</dd>
  <dt>Packages</dt>
  <dd>QEMU, `qemu-img`, UEFI firmware (OVMF or AAVMF), `ip`, `iptables`, `curl`, `sudo`</dd>
  <dt>Tool manager</dt>
  <dd>[mise](https://mise.jdx.dev/)</dd>
  <dt>Tools from mise</dt>
  <dd>`go`, `kind`, `kubectl`, `talosctl`, `yq`, `jq`</dd>
  <dt>Check</dt>
  <dd>[](lab:doctor)</dd>
</dl>

## Operating systems

| System | Result | Reason |
| --- | --- | --- |
| Linux on x86-64, with `/dev/kvm` | Works | The project builds and tests the lab on it. |
| Linux on ARM64 | Not tested end to end | The machines are ARM64 QEMU machines. A test boots an ARM64 Talos machine under TCG to its configuration. Nobody ran the full lab. |
| macOS on Apple silicon | In a Linux VM | Run the lab in an ARM64 Linux virtual machine. See [Apple silicon](#apple-silicon). |
| macOS on Intel | Does not work | There is no KVM, and Docker Desktop cannot get to the lab bridge. A Linux virtual machine with nested virtualization can work. Nobody tested it. |

The renderer selects the architecture and the accelerator of the machines. Set them in [lab.yaml](lab:page/lab-yaml) to change the selection.

| Workstation | Machines | Accelerator |
| --- | --- | --- |
| x86-64, `/dev/kvm` usable | x86-64 (`amd64`) | KVM |
| ARM64, `/dev/kvm` usable | ARM64 (`arm64`) | KVM |
| No usable `/dev/kvm` | The architecture of the workstation | TCG. QEMU emulates the CPU. A boot takes minutes. |
| Windows with WSL2 | Not tested | WSL2 must give `/dev/kvm`, cgroup v2 and Docker Engine in the WSL2 system, not Docker Desktop. |

## Install the packages

1. Install the packages for your distribution.

   | Distribution | Command |
   | --- | --- |
   | Debian, Ubuntu | `sudo apt-get install qemu-system-x86 qemu-utils ovmf curl iproute2 iptables` |
   | Debian, Ubuntu on ARM64 | `sudo apt-get install qemu-system-arm qemu-utils qemu-efi-aarch64 curl iproute2 iptables` |
   | Fedora | `sudo dnf install qemu-system-x86-core qemu-img edk2-ovmf curl iproute iptables-nft` |
   | Fedora on ARM64 | `sudo dnf install qemu-system-aarch64-core qemu-img edk2-aarch64 curl iproute iptables-nft` |
   | RHEL 9, Rocky, Alma | `sudo dnf install qemu-kvm qemu-img edk2-ovmf curl iproute iptables-nft` |
   | Other distributions | Not tested. Install the same programs. If the doctor does not find them, set `PK_METAL_QEMU`, `PK_METAL_OVMF_CODE` and `PK_METAL_OVMF_VARS`. |

2. Install Docker Engine. Use the [instructions for your distribution](https://docs.docker.com/engine/install/). See [Container engine](#container-engine).

3. Install mise. Use the [mise instructions](https://mise.jdx.dev/getting-started.html).

4. In the root of the repository, let mise read the file `mise.toml`.

   ```sh
   mise trust
   ```

5. Install the pinned tools.

   ```sh
   mise install
   ```

6. Put the pinned tools on the `PATH` of your shell. The tasks (`mise run ...`) do not need this step. The commands that you type, for example `kubectl`, need it.

   ```sh
   eval "$(mise activate bash)"
   ```

   For zsh, use `mise activate zsh`. As an alternative, put `mise exec --` before each command.

7. Check the workstation.

   ```sh
   mise run lab:doctor
   ```

   The last line is `the workstation has what the lab needs`.

On RHEL and its rebuilds, QEMU is `/usr/libexec/qemu-kvm`. The fleet finds it there.

## Apple silicon

macOS has no KVM and no Linux bridge. Run the lab in an ARM64 Linux virtual machine (VM) on the Mac.
The lab machines in that VM are ARM64 machines.

```
macOS (M1 or later)
└─ UTM: ARM64 Linux VM            ← lab/lab.sh runs here
   ├─ Docker Engine: kind node    ← the operator
   ├─ pk-metal sim fleet          ← the simulated BMCs
   └─ qemu-system-aarch64 × 3     ← the Talos machines: KVM or TCG
```

1. Install [UTM](https://mac.getutm.app/).

2. Make a VM: **Virtualize**, **Linux**, with an ARM64 server image of Debian 13 or Ubuntu 24.04.

   | Setting | Value |
   | --- | --- |
   | CPU cores | 4 or more. TCG uses one host thread for each CPU of a machine. |
   | Memory | 14 GiB for the default size. 8 GiB for `PK_LAB_NODES=1cp+0w`. |
   | Disk | 64 GiB |

3. In the VM, do the steps in [Install the packages](#install-the-packages). Use the row for ARM64.

4. Check the VM.

   ```sh
   mise run lab:doctor
   ```

   The line `the lab spec renders` names the architecture and the accelerator, for example `arm64 machines under tcg`.

| Mac | Accelerator in the VM | Reason |
| --- | --- | --- |
| M1, M2 | TCG | The hypervisor of macOS gives no nested virtualization on these chips. The VM has no `/dev/kvm`. |
| M3 or later, macOS 15 or later | KVM, if the VM has a usable `/dev/kvm` | The hypervisor of macOS can give nested virtualization on these chips. The lab uses KVM when `/dev/kvm` is usable. |

<Callout type="note">
Under TCG, each step that boots a machine takes longer. Give [](lab:wait) more time: `PK_LAB_WAIT_TIMEOUT=4800`.
The firmware-hang guard waits 3 minutes under TCG, not 90 seconds.
</Callout>

## Memory

The doctor adds the memory of all machines and 3072 MiB for kind and the fleet.
It compares the sum with the available memory.

| Role | Default memory | Default CPUs |
| --- | --- | --- |
| Control plane | 4096 MiB | 2 |
| Worker | 2048 MiB | 2 |

| Size | Machines | The doctor asks for |
| --- | --- | --- |
| `1cp+2w` (default) | 3 | 11264 MiB |
| `1cp+0w` | 1 | 7168 MiB |
| `3cp+2w` | 5 | 19456 MiB |

To change the memory of a role or of one machine, edit [lab.yaml](lab:page/lab-yaml).

## Container engine

The lab needs Docker Engine that the `docker` service of the system runs as root.

| Engine | Result | Reason |
| --- | --- | --- |
| Docker Engine, as root | Works | The kind node is on a bridge of the workstation. |
| `podman`, `podman-docker` | Does not work | The lab uses the `DOCKER-USER` chain of Docker. |
| Docker Desktop | Does not work | The engine runs in a virtual machine. The kind node cannot get to the lab bridge. |
| Rootless Docker | Does not work | The kind node is not on a bridge of the workstation. |

<Callout type="caution">
Do not add a person to the `docker` group on a shared workstation without a decision.
A member of the `docker` group has the same rights as root on that workstation.
</Callout>

## What the doctor checks

| Check | Fix when it is missing |
| --- | --- |
| `go`, `kind`, `kubectl`, `talosctl`, `yq`, `jq` | `mise install` |
| `curl` | Install the package. |
| The Docker daemon answers | Install Docker Engine and start it. |
| Docker is Docker Engine, as root | Remove `podman-docker`. Do not use Docker Desktop or rootless Docker. |
| The kernel forwards IPv4 packets (`net.ipv4.ip_forward=1`) | Restart Docker. Do not set `"ip-forward": false` in `/etc/docker/daemon.json`. |
| `docker buildx` | Install the package `docker-buildx-plugin`, or install Docker Engine from the Docker instructions. The image build needs BuildKit. |
| The kind configuration is readable | Set or unset [`PK_LAB_KIND_CONFIG`](lab:page/lab-yaml#environment-variables). |
| cgroup v2 | Boot with `systemd.unified_cgroup_hierarchy=1`, or use an older node image. See [](lab:page/troubleshooting). |
| `/dev/kvm` is usable, if the machines use KVM | Set virtualization to on in the firmware. Join the group `kvm`. Or set `accel: tcg`. |
| QEMU for the architecture of the machines, and `qemu-img` | Install the packages, or set `PK_METAL_QEMU`. |
| UEFI firmware for the architecture of the machines (OVMF, AAVMF) | Install the package, or set `PK_METAL_OVMF_CODE` and `PK_METAL_OVMF_VARS`. |
| `ip` and `iptables` | Install `iproute2` and `iptables`. |
| `sudo` | Use a terminal where `sudo` can ask for the password. |
| `firewall-cmd`, if `firewalld` is active | Install `firewalld`. |
| `NO_PROXY` includes `10.77.0.0/24`, if a proxy is set | See [Behind a proxy](lab:page/network#behind-a-proxy). |
| The outside endpoints answer | See [Outside endpoints](#outside-endpoints). |
| The lab spec renders | The message names the line to correct in `lab/lab.yaml`. |
| Available memory | Stop other programs, or use a smaller size. |
| Free disk below `.lab/` | Free some space, or set `PK_LAB_DIR`. |

The doctor changes nothing. The `sudo` check can ask for your password.

## Outside endpoints

The lab needs endpoints outside the workstation.
The doctor checks each endpoint at the same time, with a limit of 5 seconds, and shows a table.
A guest or captive network often lets the DNS server and the web traffic of the workstation through, and stops the traffic of the machines.

| Who | Endpoint | Check | For |
| --- | --- | --- | --- |
| Workstation | `https://factory.talos.dev/` | HTTPS | Boot media and schematics, for the operator |
| Workstation | `https://registry-1.docker.io/v2/`, `production.cloudflare.docker.com:443` | HTTPS, TLS | The kind node, the registry and the image build |
| Workstation | `https://gcr.io/v2/` | HTTPS | The base of the operator image |
| Workstation | `https://proxy.golang.org/` | HTTPS | The Go modules of the image build |
| Machines | Each DNS server, port 53 | A DNS query over UDP | All names. The defaults are `1.1.1.1` and `8.8.8.8`. |
| Machines | Each NTP server, port 123 | An SNTP request over UDP | The clock. The default is `time.cloudflare.com`. |
| Machines | `https://factory.talos.dev/v2/` | HTTPS | The installer image |
| Machines | `https://ghcr.io/v2/`, `pkg-containers.githubusercontent.com:443` | HTTPS, TLS | The kubelet and flannel |
| Machines | `https://registry.k8s.io/v2/` and the mirror that it sends to | HTTPS | The control plane, etcd and CoreDNS |
| Machines | `discovery.talos.dev:443` | TLS | Cluster discovery |

- The requests of the workstation use its proxy, if `HTTPS_PROXY` is set.
- The requests of the machines go through the NAT of the workstation, without its proxy. The doctor sends them from the workstation, on the same way out.
- The doctor reads the servers of the machines from the `patches` list of [lab.yaml](lab:page/lab-yaml): DNS, NTP, discovery, registry mirrors and proxy. Without a patch, the doctor uses the defaults of Talos.
- For a registry with a mirror, the doctor checks the mirror.
- Any HTTP status, also `401`, shows that the way is open.
- A certificate that the workstation does not trust shows a captive portal or a TLS proxy on the way.
- The doctor shows `warn` for the NTP servers and the discovery service, and continues. Without NTP, each boot waits 2 minutes for the clock. Without the discovery service, `talosctl get members` shows no members. Kubernetes and etcd work without it.
- For each `MISS` or `warn` line, a `fix:` line follows the table. To change the servers of the machines, see [Behind a proxy](lab:page/network#behind-a-proxy).
