## Terms

<dl>
  <dt>Assertion</dt>
  <dd>A fact that you write: the serial number of a machine, the install disk, the Talos version.</dd>
  <dt>Observation</dt>
  <dd>A fact that the operator reads from a BMC, a node or etcd, and writes in a status.</dd>
</dl>

## The identity of a machine

A machine has one identity: its serial number.
Two independent sources give it: you, in the [](kind:Asset), and the BMC, through Redfish. The operator continues only when they agree.
The operator does not guess which side is correct. If they disagree, the endpoint goes to `Mismatch`, and nothing happens to the machine. See [](rb:host-mismatch).

<dl>
  <dt>Serial anchor</dt>
  <dd>The serial number that the operator reads for a vendor. A Supermicro system gives the board serial. A Huawei system gives the chassis serial.</dd>
  <dt>Host name</dt>
  <dd>The serial anchor in lower case. Each path to the same machine gives the same [](kind:Host). If the facts of two paths differ, the Host shows `Inspected=False` with `IdentityDiverged`, and the operator holds it.</dd>
  <dt>Verified</dt>
  <dd>The condition that says that the two sources agree. `False` with `SerialMismatch`: the serials differ. `False` with `MACMismatch`: the BMC at the ledger address reports a different MAC address, so the ledger points to another machine.</dd>
</dl>

Why two sources:

- A wrong cable or a wrong ledger line can point an Asset to another machine.
- If the operator trusted one source, it could install the wrong machine.
- The identity does not use the address, the endpoint name or the BMC firmware.

## Why it helps

- Your git repository holds only assertions. You can apply it again at each time.
- The status tells what is true now, not what someone wished.
- A change made by hand shows as drift, not as a new truth. See [](concept:drift).
