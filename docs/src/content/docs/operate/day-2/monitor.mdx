## Goal

See what runs, what waits and what is wrong, from a quick look to a page.

## Three ways to look

| Tool | For | Reads |
| --- | --- | --- |
| [](cli:status) | A quick look, a cron check | The management cluster |
| [](cli:top) | A live view, one tile for each machine | The management cluster |
| Prometheus metrics and alerts | Dashboards and pages | The `/metrics` endpoint of the manager |

## Use pk-metal status in a check

<Steps>

1. Run the command and read its exit status.

   ```sh
   pk-metal status; echo "exit=$?"
   ```

2. Read the result.

   <CliExit cmd="status" />

3. For a script, use the JSON form.

   ```sh
   pk-metal status -o json
   ```

</Steps>

## Start the alerts

<Steps>

1. Make sure that the cluster has the Prometheus Operator. The files use its kinds `PrometheusRule` and `ServiceMonitor`.

2. Open `metal/config/prometheus/metrics_reader.yaml`. Set the subject of the `ClusterRoleBinding` to the service account of your Prometheus.

   The manager serves `/metrics` over HTTPS. It answers only a caller whose token may `get` the URL `/metrics`.

3. If your Prometheus selects ServiceMonitors by a label, add that label to `metal/config/prometheus/servicemonitor.yaml`.

4. Apply the rules, the ServiceMonitor and the role.

   ```sh
   kubectl apply -k metal/config/prometheus
   ```

5. Make sure that Prometheus scrapes the manager. In Prometheus, this query gives `1`.

   ```text
   up{job="pk-metal-metrics", namespace="pk-metal"}
   ```

</Steps>

Each alert has a `runbook_url` annotation. It links to the runbook.

| Alert | Fires when | Runbook |
| --- | --- | --- |
| `PkMetalMetricsAbsent` | Prometheus did not scrape the manager, for 10 minutes | [](rb:management-cluster-lost) |
| `PkMetalAdmissionGateDegraded` | An admission policy of the approval gate, or its binding, is missing or does not deny, for 2 minutes | [](rb:admission-gate-degraded) |
| `PkMetalReconcileFailing` | More than half of the passes of one controller fail, for 30 minutes | [](rb:reconcile-failing) |
| `PkMetalReconcilePanicked` | A controller panicked in the last hour | [](rb:reconcile-failing) |
| `PkMetalOperationWorkersBusy` | Each operation worker is busy, for 1 hour | [](rb:workers-busy) |
| `PkMetalOperationFailed` | An operation failed, for 5 minutes | [](rb:operation-failed) |
| `PkMetalOperationStuck` | An operation is in one step for more than 2 hours | [](rb:operation-stuck) |
| `PkMetalOperationBlocked` | An approved operation did not start for 1 hour, and no window or queue holds it | [](rb:operation-held) |
| `PkMetalApprovalWaiting` | An operation waits more than one day for approval | [](rb:operation-held) |
| `PkMetalBMCUnreachable` | A BMC does not answer, for 15 minutes | [](rb:bmc-unreachable) |
| `PkMetalNodeNotReady` | A node that answered before is not `Ready`, for 15 minutes | [](rb:node-not-ready) |
| `PkMetalClusterUnavailable` | A bootstrapped cluster is not available, for 15 minutes | [](rb:cluster-unavailable) |
| `PkMetalEtcdBackupStale` | The newest verified backup is older than two backup intervals | [](rb:backup-failing) |
| `PkMetalEtcdBackupMissing` | A backup policy has no verified snapshot after 1 hour | [](rb:backup-failing) |
| `PkMetalCredentialsExpiring` | A published credential has less than one sixth of its lifetime left | [](rb:credentials-not-renewed) |
| `PkMetalRolloutStalled` | A rollout waits for health, cannot plan, or waits after its first node, for 1 hour | [](rb:rollout-paused) |
| `PkMetalRolloutFailed` | A rollout ended without finishing | [](rb:rollout-paused) |

<Callout type="caution">
`PkMetalMetricsAbsent` cannot page when Prometheus stops together with the management cluster.
Send this alert to a receiver outside the management cluster, or watch the manager from a second Prometheus.
</Callout>

The base install has the NetworkPolicy `pk-metal-manager`. Each address can reach `/metrics`. To limit it to your Prometheus, patch the policy in your overlay, as `metal/config/samples/site-overlay/networkpolicy.yaml` does. See [](ref:media-store#network-policy).

To check the rules with `promtool`, run `mise run metrics:rules`.

## Metrics

All series start with `pk_metal_`. [Metrics](ctrl:manager#metrics) lists them.
The alerts use the `expected_*` series, so an install does not page.
