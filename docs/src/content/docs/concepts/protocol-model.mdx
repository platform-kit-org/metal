The operator changes a machine through some controllers that work together.
Each controller reads a cache that can be late, and a process can stop at each point.
A TLA+ specification and three model tests check the protocol across many orders of events.

## The checks

| Check | What it checks | Size |
| --- | --- | --- |
| `TestProtocolModel` | Each order of turns of the controllers, a person and the machine, with stale reads | 14 turns, about 40 seconds |
| `TestExecutorModel` | The real executor against the Redfish simulator, with faults and process stops | 300 cases from a fixed seed |
| `spec/claimhost` (TLA+, `mise run spec`) | Each order of events of the Host hand-off between claims: bind, release, unbind, and the Host phase. Each kind has its own late cache | 3 configurations, about 10 seconds |
| `TestStaleReadClaimHost` (controller test) | The real claim and Host controllers on each cache state that one pass can read along the life of a claim | about 110 passes, about 12 seconds |

## Terms

<dl>
  <dt>World</dt>
  <dd>The full system state as one value: one Host, one claim, the machine, three operation slots.</dd>
  <dt>Stale read</dt>
  <dd>A controller reads an object kind from the world one turn before. The model tries each choice.</dd>
  <dt>Invariant</dt>
  <dd>A rule that must be true after each turn. For example: at most one started operation runs on a Host.</dd>
</dl>

## Selected invariants

1. At most one started, unfinished operation runs on a Host.
2. Only an approved operation mounts media.
3. A machine that a boot touched is unbound only after a release turned it off.
4. A release of a machine that ran its node waits for a person.
5. A power action on a control plane of the operator cluster starts only with `metal.platform-kit.org/allow-self-disruption`.

The model calls the same helper functions as the controllers. Only the control flow is written again in the test.
A `// go:` line above each pass of the model keeps a hash of the function whose control flow the pass writes again. `TestSpecSync` checks these lines and the `\* go:` lines of the TLA+ specification. A change of the code of such a function fails the test, so that a person brings the model in line before the hash changes. A change of a comment does not count.

## The hand-off of a Host: TLA+ and stale reads

`TestProtocolModel` checks the Host phase from the true world. The Host controller does not see the true world.
It reads its caches, and each kind has its own cache.
A cache is late, but it never shows an older version again. Two caches can be late by different amounts.
The TLA+ specification `metal/spec/claimhost/ClaimHost.tla` models exactly this.

TLC, the TLA+ model checker, checks these rules in each state:

1. A claim that reports `Bound`, and that is not in deletion, holds the Host.
2. The claim finalizer goes only after no Host carries the claim.
3. No claim takes the Host from a claim that still exists.
4. A machine that a boot started is unbound only after the release turned it off.
5. No controller writes `Assigned`, `Provisioning`, `Provisioned` or `Failed` from a bind that the API server already ended.

Rule 5 is the race of a release. The claim cache shows no claim.
But the Host cache still shows the old `claimRef`, the OS and `OSReady=True`.
The old phase derivation then wrote `Provisioned` after `Releasing`.
`MC_cache.cfg` keeps that old derivation, and `mise run spec` fails if TLC does not find the violation.
That proves that rule 5 catches the race.
`mise run spec` also fails if the model cannot reach each state that the rules are about.

`TestStaleReadClaimHost` runs the real controllers on the same idea.
It follows the life of a claim with fresh reads: bind, hand-off, delete, release, unbind, a second claim.
After each step, it runs each controller once on each combination of late caches, and sends each write as a dry run.
The API server checks the write, but does not keep it. The test checks the rules above on each write that the API server accepts.
A cache cannot be behind the last pass on the path. All controllers read the same caches, and a cache never shows an older version again.

### Keep the specification and the code in step

- Each operator of the specification names the Go functions it mirrors in a `\* go:` line, with a fingerprint of their code.
- `TestSpecSync` (part of `mise run test`) fails when one of these functions changes or is gone.
- When it fails:
  1. Read the operator. Change it if the code does something new.
  2. Run `mise run spec`.
  3. Record the new fingerprints with `go test ./spec -run TestSpecSync -update`.
- The configurations of the specification and `TestStaleReadClaimHost` check invariants with the same names. `TestSpecSync` compares the two lists.

## Known limit

A hold set right after the deletion of a claim does not stop a release that needs no approval.
To keep a machine, hold the claim before you delete it.
