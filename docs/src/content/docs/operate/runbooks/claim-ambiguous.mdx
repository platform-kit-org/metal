## Symptoms

<dl>
  <dt>[](kind:HostClaim) phase</dt>
  <dd>`Ambiguous` or `Pending`.</dd>
  <dt>`BLOCKED`</dt>
  <dd>`AmbiguousSystem`, `SystemNotFound`, `HostAlreadyClaimed`, `AssetNotFound`, `AssetNotMaterialized` or `HostNotDiscovered`.</dd>
</dl>

## Impact

The claim holds no machine. The operator installs nothing.

## Diagnose

<Steps>

1. Read the claim.

   ```sh
   kubectl -n default describe hostclaim cp-1
   ```

2. For `AmbiguousSystem`, read the systems of the endpoint.

   ```sh
   kubectl describe managementendpoint sim-0001
   ```

   Each entry in `Systems` is one machine.

</Steps>

## Fix

| Reason | Fix |
| --- | --- |
| `AmbiguousSystem` | Set `spec.systemRef.name` to the system ID from `Systems`. |
| `SystemNotFound` | `spec.systemRef.name` names no system. Use an ID from `Systems`. |
| `HostAlreadyClaimed` | Another claim holds the Host. The first claim wins. Use another Asset, or release the other claim. |
| `AssetNotFound` | `spec.assetRef.name` names no Asset. |
| `AssetNotMaterialized`, `HostNotDiscovered` | The operator did not find the machine yet. See [](rb:bmc-unreachable). |

## Verify

The claim phase is `Bound`.
